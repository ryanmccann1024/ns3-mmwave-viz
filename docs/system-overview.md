## Simulator

The companion **ns3-mmwave** simulator (`scratch/mesh-sim`) parses its CLI, loads a scenario (`run.ini` + `nodes.json`, plus optional `buildings.json` / `jammers.json`) and runs a per-tick loop that evaluates every link, routes traffic and writes metrics. Its Python tools (field-data pipeline, validation, sweeps, RL, baselines, plotting) build scenarios and launch an already-built binary. Its documentation is the authority on all of that; reach it through the companion link on the \ref index "landing page".

## Data boundary

The simulator writes each run under `outputs/YYYY-MM/DD/HH-MM-SS/seed-N/`: per-tick `positions.csv` and `links.csv`, with `#key=value` header comments carrying the simulation metadata, plus optional `buildings.json` and RL artifacts. This visualizer only reads those files. The simulator owns the artifact contracts (fields, units, schema versions); this project documents what it derives from them and how it behaves when a value is missing. Do not restate field definitions here — link to the simulator's `CONTRIBUTING.md` and module pages via the companion site.

## Visualizer

**Open Data Folder** hands a directory to run discovery, which groups valid runs by date. Selecting a run parses its CSV/JSON files into frames; the playback state machine advances through them while the Three.js canvas renders nodes, links, buildings and jammers, and the RL experiment pages read saved training/evaluation results. The README's \ref viz_readme_architecture "Architecture Overview" lists the `src/` tree, and the \ref source_map "Source map" groups the files by what they do.
