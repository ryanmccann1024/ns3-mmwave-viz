# Generating the docs {#generating_the_docs}

[TOC]

This site is generated by Doxygen from the Markdown pages in `docs/` plus the repository `README.md`, styled with the vendored doxygen-awesome-css theme. Nothing is extracted from the TypeScript sources; guides are authored by hand with direct links into `src/`. The Generate block starts at the repository root and changes into `docs/`, where `Doxyfile` lives. Run generation and the Open commands from that docs directory.

## Tested versions

| Component | Tested (this host) | Declared compatibility |
|---|---|---|
| Doxygen | 1.18.0 | Theme README at v2.5.0: "Works best with Doxygen 1.9.1 - 1.9.4 and 1.9.6 - 1.18.0" |
| doxygen-awesome-css | v2.5.0, commit `46483f1e5a70ffb9ecd3b82d0a1cd1b24edf13da` | Recorded in `theme/provenance.md` |

Tested host: macOS, October 2026, with `doxygen` from `/usr/local/bin`. Graphviz is not needed: the system diagram is a pre-generated SVG. Other operating systems are untested here; the commands below for them come from the tools' own documentation.

## Install the tools

```bash
# macOS (Homebrew) — the tested host
brew install doxygen
# Debian / Ubuntu — untested here
sudo apt install doxygen
```

Other platforms: Doxygen downloads at <https://www.doxygen.nl/download.html>. Check with `doxygen --version`. A Doxygen version other than 1.18.0 may emit configuration warnings or render differently; the theme's supported range is in the table above.

## Generate

```bash
cd docs
doxygen Doxyfile          # warnings → doxygen-warnings.log
```

Output goes to `docs/html/`. Re-run after editing any Markdown page listed in `INPUT` (the four pages here and `../README.md`). `html/` and `doxygen-warnings.log` are ignored by `docs/.gitignore`; never commit them.

## Open

```bash
open html/index.html        # macOS
xdg-open html/index.html    # Linux
```

Or open `html/index.html` through the browser's file picker. The site is a set of local files; there is no server to start.

## Warnings

Doxygen writes its diagnostics to `doxygen-warnings.log` in this directory (`WARN_LOGFILE`). A "does not exist" error naming a stylesheet or extra file means the theme directory is missing or incomplete (see below).

## Theme and provenance

The theme files live in `theme/doxygen-awesome-css/`: eight files copied unchanged from the upstream release, MIT licence included. `theme/provenance.md` records the tag, commit, archive hash, per-file hashes and the exact commands to re-acquire or verify them. `header.html` is the simulator site's header, kept the same apart from its sidebar captions: Doxygen 1.18.0's stock template plus the theme's four extension scripts (dark-mode toggle, fragment copy button, paragraph links, interactive table of contents), Google Fonts links for Lato and Roboto Slab, a project-name link to the home page, and a separate script block that keeps the sidebar synced, adds the sidebar group captions, adds the text-size control at the bottom of the sidebar and shows authored diagrams as scalable images. The text size is stored under the same key as on the simulator site, so opened from local files both sites use one setting.

Site-specific styling lives in `theme/viz.css`, loaded last through `HTML_EXTRA_STYLESHEET` so it overrides the theme without editing the vendored files. It is a copy of the simulator site's `theme/mesh-sim.css`, so the two companion sites look the same: the Read the Docs look of the FUSION documentation, with colours for light and dark mode, the sidebar, one heading scale for every page, table and code sizing, the "On this page" box, diagram sizing and the landing-page styles. Keep it in step with that file. Its `--side-nav-fixed-width` must equal `TREEVIEW_WIDTH` in `Doxyfile` (both 340 px). If you upgrade Doxygen, regenerate a stock header in a scratch directory with `doxygen -w html header.html footer.html stylesheet.css` and re-apply those insertions.

The sidebar lists the home page's subpages, in the order of the `\subpage` links in the "How These Docs Are Organized" table on `index.md`; the group captions in `header.html` must name the first page of each group, so update both together. `DoxygenLayout.xml` is the simulator site's layout file; with no extracted code its API entries stay empty and are not shown.

## Troubleshooting

- **No styling or no dark-mode button** — `theme/doxygen-awesome-css/` is missing or incomplete; restore it with the steps in `theme/provenance.md`.
- **System overview figure missing** — `diagrams/system-overview.svg` is missing; run `python3 diagrams/system-overview.py` from `docs/` (Python 3, standard library only).
- **"Tag ... has become obsolete"** — you are running a Doxygen version other than 1.18.0; remove the flagged line or adjust `Doxyfile` for your version.
- **A page did not change after editing** — confirm the file is listed in `INPUT`, then re-run `doxygen Doxyfile`.
